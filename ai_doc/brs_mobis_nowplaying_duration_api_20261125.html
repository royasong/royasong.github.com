NowPlaying duration 전달 경로: brs → PAL → 모비스 SDK (2026-11-25)

대상: ccNC 143 brs (Audio+ / pickaudioweb) 저장소: brs_143, webappmanager-plugin-pal, webcommonhmi SDK: mobis-ccnc sysroot mediagatemanager-interface

Now Playing Bar(NPB)·홈 위젯·NPP의 재생 시간(duration)이 brs의 어디에서 시작해서 어떤 모비스 SDK API로 넘어가는지 코드 기준으로 정리했습니다. 코드 수정은 없습니다.

요약

  • 모비스로 duration을 보내는 SDK API는 mediagatemanager::NowPlayingProvider::setNowPlayingInfo()입니다. duration은 세 번째 인자 NowPlayingInfo의 setDuration(HUInt64)에 담깁니다.
  • guideJson에는 duration이 없습니다. guideJson에는 actions, artist, category, serviceName, appId, imageUrl이 들어갑니다.
  • 값의 출처는 Chromium MediaSessionImpl::RebuildAndNotifyMediaPositionChanged()의 position_->duration().InMilliseconds()입니다. 단위는 ms입니다.
  • 재생 위치(position)는 별도 API NowPlayingProvider::setPlayPosition()으로 갑니다.
  • webcommonhmi의 QVariantMap data["duration"]은 모비스로 보내는 값이 아닙니다. webcommonhmi가 MediaGate에서 받은 NowPlayingInfo::getDuration()을 자기 NPP 화면 QML로 넘기는 값입니다.
  • Video+(picknowweb)는 진행률을 표시하지 않으므로 brs가 duration을 0으로 보내고 position은 보내지 않습니다.

확인할 때 볼 로그와 주의점

  • brs 송신: AudioImpl::setMetadata source : … duration : <ms>, 성공 시 AudioImpl::setMetadata success
  • webcommonhmi 수신: NowPlayingManager::onNowPlayingInfoChanged source: … duration: <ms>
  • AudioImpl::setMetadata()는 title/artist/duration이 모두 이전과 같으면 보내지 않습니다(force 제외).
  • Audio::setMetadata()는 앱 이름을 비동기로 받은 뒤 전송합니다. 그래서 요청 시점의 status를 들고 늦게 도착할 수 있습니다(Audio+ 재생 버튼 상태 어긋남 참고).
  • 라이브 스트림은 Chromium에서 duration이 is_max()입니다. 이 값이 InMilliseconds()로 변환되어 그대로 전달될 수 있으니, 라이브 CP에서 progress bar가 이상하면 이 값을 먼저 확인합니다(코드상 추정, 실기기 미확인).
