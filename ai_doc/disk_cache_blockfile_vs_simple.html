4. 삭제 동작

항목blockfilesimple
기간별 삭제 (DoomEntriesBetween)지원 (최근 사용 순 목록을 돌며 기간 내 항목 삭제)지원
전체 기간 삭제열린 항목이 없으면 캐시 파일을 지우고 새로 생성 (RestartCache)항목 파일을 하나씩 삭제
삭제 후 디스크 사용량 (du)전체 삭제: 바로 줄어듦 (열린 항목이 없을 때)
기간별 삭제: 일부만 줄어듦
- 16KB 초과 항목(f_*): 파일 삭제 → 줄어듦
- 16KB 이하 항목(data_0~data_3): 블록을 빈 칸으로 표시만 하고 파일 크기는 그대로 (빈 칸은 이후 재사용)		지운 항목 파일이 삭제되어 바로 줄어듦
삭제 속도 (타겟)빠름 (파일 몇 개만 다룸)항목이 많으면 느림 (파일 수만큼 unlink, HKMCCCNCMO-5374)
사용 중인 항목재생 중인 미디어 등 열려 있는 항목은 삭제 표시만 되고, 닫힐 때 실제로 삭제됨 (두 백엔드 공통)

6. 정리

  • blockfile (mobis): 삭제가 빠르고 전체 삭제 시 용량이 확실히 줄어듦. 대신 설정 화면의 기간별 용량은 항상 전체 크기("최대 xx MB")로 표시됨.
  • simple (motrex): 기간별 용량이 정확히 표시되고 삭제 즉시 용량이 줄어듦. 대신 캐시 항목이 많으면 타겟에서 삭제가 느림.
  • 기간별 정확한 용량이 필요하면 blockfile용 기간별 크기 계산(OpenIterator + GetLastUsed/GetDataSize)을 직접 구현해야 함 (Chromium 미구현, 캐시가 크면 계산이 느림).
