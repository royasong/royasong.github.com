ccnc에서 adblock은 꺼져 있음

  • 코드: ccnc(!MOTREX_CCNC)는 StartWatchingAdBlockPref()가 obigo.adblock.enabled를 기본값 false로 지웁니다(webappextension_delegate_impl.cc:1555, startup_browser_creator_impl.cc:226). 이 pref를 켜는 Settings 토글은 #if OBIGO_AD_BLOCK && MOTREX_CCNC 전용(prefs_util.cc:386)이고, SetAdBlockEnabled를 부르는 곳은 ApplyAdBlockToNetworkService 하나뿐입니다. 꺼져 있으면 setPicknowCountryCode/setPicknowBaseUrl도 목록을 재로드하지 않습니다. ✔
  • 로그: 로컬 ccnc DLT 로그 49개(stress_test 2026-11-06, 2026-10-08~10-15, 2026-11-17)에서 ApplyAdBlockPref : 0 123회, InitAdBlockService 61회만 나오고 ApplyAdBlockPref : 1, AdBlockService::(목록 다운로드), Parse failed는 0회입니다.
  • 결론: adblock 목록 관련 누수(deserialize 버퍼, selector 누적, 탭별 JSON 사본, 다운로드 테스트 루프)는 ccnc에서는 발생하지 않고, adblock을 켜는 MOTREX에 해당합니다.
  • 꺼져 있어도 남는 비용: RenderFrameImpl::DidCreateDocumentElement의 GetAdBlockCssFilters 동기 IPC는 renderer에 enabled 검사가 없어 모든 문서마다 나갑니다(browser가 빈 목록 반환). WebContents마다 AdBlockDelegate observer가 등록되고 지워지지 않습니다.

ccnc 기준 10MB+ 후보는 GStreamer 버스 메시지와 url_list_ 2건입니다.

요약

  • 가장 큰 누수: ccnc는 GStreamer 버스 메시지 누적과 네비게이션마다 커지는 url_list_, MOTREX는 여기에 adblock 필터 갱신 버퍼가 더해집니다.
  • 가장 큰 CPU 부담: 프레임·문서·미디어 로드마다 나가는 renderer 동기 IPC(AudioManager, 도메인 필터, adblock CSS), video-hole draw마다 PostTask와 매 갱신 레이어 전체 순회, GStreamer duration 재시도 100µs 루프, 로그 한 줄당 비용.
  • 안정성: 볼륨 long-press lambda의 dangling reference(UAF), CDM 타이머 빈 map 역참조, adblock matches() 경합, gamepad raw WebContents*.
  • obigo/port 영역은 심각한 누수나 폴링은 없고, 앱 실행마다 반복 초기화와 Now Playing 중복 IPC 정도입니다.

10MB+10MB 이상 메모리 누수가 예상되는 항목

크기는 코드 기준 추정치이고, 실측은 guider PSS로 해당 프로세스 추이를 봅니다. adblock 데이터는 단말 OAF/easylist.txt(2019년판 원문, 코드에서 읽지 않음)가 아니라 서버(/v2/adblock/filter/<name>?fileType=zip&serialize=Y)에서 받은 직렬화 .dat 3개(easylist·국가·CUSTOM)이므로, 회당 누수량은 단말 ~/ad-block/*.dat 크기 합계입니다.

3. 안정성

  • ✔ 볼륨 연속 조절 (media_device_handler_ccnc.cc:324): lambda가 app_id = a_app_id로 복사해 두고도 본문에서 a_app_id(호출자의 const std::string&)를 써서, startContinuousVolumeControl 반환 후 dangling reference → long-press마다 use-after-free. 또 RELEASE 없이 LONG이 두 번 오면 joinable std::thread에 대입해 std::terminate. 본문을 app_id로 바꾸고, 시작 전 stop/join.
  • ✔ CDM 타이머 (media/cdm/cdm_adapter.cc:817-838, OBIGO_DRM_WIDEVINE): 만료 시각(ms)을 키로 std::map에 insert해 같은 ms면 두 번째가 무시되는데 PostDelayedTask는 두 번 나가므로, 두 번째 WrappedTimerExpired가 빈 map의 begin()을 역참조(UB·크래시). 맨 앞 항목을 꺼내는 방식이라 다른 타이머 context가 먼저 실행될 수도 있음. upstream처럼 BindOnce(&CdmAdapter::TimerExpired, weak, context)로 복원.
  • ✔ adblock (MOTREX): network 스레드 OnBeforeURLRequest(:249-261)가 is_ready_ 확인 후 client_->matches()를 부르는데, ThreadPool PushContents가 락 없이 같은 static client_에 clear()/deserialize() → 해제된 메모리 접근 가능. do_update_/update_retry_도 atomic 아님.
  • ✔ gamepad (OBIGO_GAMEPAD): 싱글턴이 WebContents*를 raw로 보관(gamepad_manager.h:64, gamepad_event_manager.h:67)하고 stopGamepad()에서도 지우지 않음. worker 스레드에서 읽고 UI task에 raw 바인딩. GetWeakPtr() 또는 WebContentsObserver로.
  • ✔ obigo/port/media/ccnc/Audio.cc:232-233: parse(..., nullptr, false)가 실패하면 discarded 값을 반환하고, 다음 줄 jvalue["appId"] = ...가 discarded·비object JSON에서 type_error.305를 던짐. 잡는 곳이 없어 std::terminate. if (!jvalue.is_object()) jvalue = json::object();.

  1. GStreamer 버스 메시지 누수, duration 재시도 Milliseconds(100) + 상한
  2. url_list_를 커밋된 origin set으로(서브프레임 포함, same-document 제외), ClearData 비밀번호 목록 1회 조회

  4. haudiosink unref, adblock observer RemoteSet, Null sink wrapper renderer
