Release build DevTools(Inspector)·CDP 차단 검토 (2026-11-24)

release build에서 키보드·마우스·원격 접속으로 inspector를 열 수 있는지, AI의 CDP 자동화가 되는지, 설정값으로 CDP만 켤 수 있는지를 정리했습니다. 코드를 읽고 판단한 결과이며, 단말에서 직접 확인하지는 않았습니다.

1. 결론

release build(obigo_release_mode=1)에서 inspector에 들어갈 수 있는 경로가 없습니다. AI를 이용한 CDP 자동화(guider_auto_* 스킬 등)도 release에서는 동작하지 않습니다.

개발용 build(release 아님)는 기존과 같아서 9222 포트로 CDP를 쓸 수 있습니다.

obigo_release_mode=1은 build/buildscripts/OAF/brs/BRSBuild_Browser_for_143.sh:280에서 SET_RELEASE_MODE가 켜져 있을 때만 들어갑니다.

공통 핵심은 devtools_availability_checker.cc입니다. WebContents용 IsInspectionAllowed는 어떤 분기로 가든 결국 extension용이나 web_app용 함수를 부르고, release에서 이 두 함수가 무조건 false라서 창 생성, inspector 화면, CDP 세션 세 단계가 한꺼번에 막힙니다.

남는 경로와 참고 사항

  • 해당 없음 service worker·shared worker에 CDP를 붙일 때는 ShouldAllowSession 같은 확인이 없어서, debugger 권한을 가진 확장이 있으면 chrome.debugger로 worker에 붙을 수 있습니다. 하지만 OFFICIAL_BUILD(--release·--internal-release 모두)에서는 기본 옵션에 --disable-extensions가 들어가고(command_line_obigo.c.h:121), brs 소스에 그런 확장 manifest도 없어 실제로는 해당이 없습니다.
  • obigo_remote_debug_ui.cc, controller_manager.cc(StartRemoteControllingServer), obigo_internals_handler.cc는 어떤 BUILD.gn에도 들어 있지 않아 빌드에 포함되지 않습니다. 따라서 진입 경로가 아닙니다.
  • chrome://inspect 확인은 host를 정확히 "inspect"로 비교합니다. Chrome이 WebUI를 찾을 때도 정확히 비교하므로 inspect. 같은 변형으로는 inspect 페이지가 뜨지 않습니다.

단말 확인 방법 (미수행)

  • release deb에서 F12, Ctrl+Shift+I를 눌러도 아무 반응이 없는지
  • --remote-debugging-port=9222를 붙여 실행한 뒤 ss -ltn에 9222가 없는지
  • devtools://devtools/bundled/inspector.html로 이동했을 때 차단되는지

6. (보류) webappmanager.config 설정으로 release에서 CDP만 켜기

상태: 2026-11-24 검토만 하고 중단. 코드는 수정하지 않았습니다.

현재 막혀 있는 이유

  • chrome_main.cc:193: release에서는 AddOptionFromConfigForWebSolution()을 호출하지 않음
  • command_line_obigo.c.h:430: 파서 함수 자체가 #if !BUILDFLAG(OBIGO_RELEASE_MODE) 안에 있음

구현안 (설정 키 예: enable-cdp:on)

파일내용
content/public/app/command_line_obigo.c.hrelease 전용 작은 파서 추가. $OBIGO_AF_DIR/configuration/webappmanager.config에서 enable-cdp:on 한 줄만 보고, on이면 --remote-debugging-port=9222, --remote-allow-origins=* 추가. 다른 키는 release에서 계속 무시
chrome/app/chrome_main.ccrelease 분기에서 위 함수 호출
chrome/browser/browser_process_impl.ccrelease여도 CDP가 on이면 원래의 RemoteDebuggingServer 기동 경로를 탐
chrome/browser/devtools/chrome_devtools_manager_delegate.ccAllowInspectingRenderFrameHost()만 CDP가 on일 때 true (페이지 세션만 허용)
  • on/off 판단은 browser 쪽에서 config 파일을 직접 읽어 정합니다. 명령줄 스위치로 판단하면 실행 인자에 그 스위치를 넣는 것만으로 우회되기 때문입니다.
  • on일 때도 IsInspectionAllowed()는 false로 두어 F12, 컨텍스트 메뉴, 단말 화면의 DevTools 창은 계속 막고, devtools://, chrome://inspect 차단도 유지합니다. 열리는 것은 CDP 소켓 하나뿐입니다.

정해야 할 것

  1. 어느 주소로 열지
    • (추천) 127.0.0.1만: 단말 밖에서는 직접 접속할 수 없고, PC에서는 ssh -L 9222:localhost:9222 <단말>로 터널을 열어서 붙습니다. guider_auto_* 스킬은 이미 SSH를 쓰므로 터널 한 줄만 추가하면 됩니다. release에서는 OBIGO_INSPECTOR_ADDRESS가 꺼져 있어 기본 동작이 127.0.0.1입니다.
    • 단말 IP(eth/wlan)로 열기: 개발용 build와 똑같이 PC에서 바로 붙을 수 있지만, 같은 네트워크에 있는 누구나 접속할 수 있습니다.
  2. 보안 리스크를 받아들일지: 단말에서 config 파일에 쓸 수 있는 사람이면 누구나 release에서 CDP를 켤 수 있게 되어 release 차단의 의미가 일부 약해집니다. 양산 단말에서 webappmanager.config 쓰기 권한이 root로 제한돼 있는지 확인이 필요합니다.

127.0.0.1(단말 내부)로 열 때의 접근 조건

  • 9222 포트는 단말 자기 자신만 접속할 수 있습니다. 같은 네트워크의 PC라도 <단말IP>:9222로는 붙을 수 없습니다.
  • PC에서 쓰려면 SSH 터널이 필요합니다. 단말 SSH는 항상 id/pw를 요구하므로, CDP를 쓸 수 있는 사람은 단말 id/pw를 아는 사람으로 한정됩니다. config 파일 수정도 같은 로그인이 필요해서 위 보안 리스크도 같은 보호를 받습니다.
  • 남는 경로: ① 단말 안의 다른 프로세스는 id/pw 없이 127.0.0.1:9222에 붙을 수 있습니다(config가 on일 때만). ② --remote-allow-origins=*를 넣으면 웹페이지 JS의 WebSocket 접속도 허용 대상이 되므로 이 옵션은 넣지 않습니다. Python websocket이나 Puppeteer 같은 자동화 클라이언트는 Origin을 보내지 않아서 이 옵션 없이도 동작합니다.

7. 빌드 옵션 검토: --release vs --internal-release

결론: 지금 구조가 맞습니다. 외부 배포용 --release에서는 모두 막고, 내부 QC용 --internal-release에서는 열어 두는 것이 빌드 스크립트의 원래 설계이며, 이번 코드도 그 기준을 그대로 따릅니다.

# 외부 릴리즈

8. 기존 코드(HEAD)에서는 --release에서도 CDP 가능

결론: 이번 수정(미커밋)을 빼고 커밋된 코드 기준으로 보면, --release 빌드에서도 CDP를 쓸 수 있는 경로가 있습니다. 이번 수정을 커밋해야 완전히 막힙니다.

기본 동작은 막혀 있음

  • obigo_inspector_address가 꺼져 있어 9222 기본 옵션이 들어가지 않습니다.
  • webappmanager.config를 읽지 않습니다.
  • 실행 인자는 허용 목록(ObigoUserAcceptableCommandLineOption)에 있는 것만 통과하고, --remote-debugging-port는 목록에 없습니다.

우회 경로: private 옵션 모드

  • content/public/app/command_line_obigo.c.h:309 AddCommandLineOption() → CheckIsObigoPrivateOption()(:715) / AddObigoPrivateOption()(:726)
  • 실행 인자에 소스에 하드코딩된 비밀 문자열(ObigoExecPassWord, 값은 생략)이 있으면 허용 목록 검사 없이 모든 실행 인자를 그대로 통과시킵니다.
  • 이 모드는 OBIGO_RELEASE_MODE 조건 없이 항상 켜져 있습니다.
SSH 로그인(단말 id/pw)
→ 브라우저를 [비밀 문자열] --remote-debugging-port=9222 로 직접 실행
→ 127.0.0.1:9222 CDP 서버 기동 (IsInspectionAllowed도 허용 상태)
→ SSH 터널로 PC에서 CDP 사용 가능
  • 필요한 것: 단말 SSH id/pw + 비밀 문자열
  • 단말 IP로는 열리지 않아서(obigo_inspector_address 꺼짐) 네트워크에서 바로 붙을 수는 없고, SSH 터널을 거쳐야 합니다.
  • 기존 코드에는 inspector 단축키(F12, Ctrl+Shift+I)와 devtools:// 이동을 막는 코드도 없었습니다. 단말에 키보드를 연결할 수 있는 환경이면 화면에 DevTools 창이 뜰 수 있는 구조입니다(단말 미확인).

  • private 옵션 모드는 release에서도 비밀 문자열 하나로 모든 실행 인자 제한을 풉니다(예: --disable-web-security, 확장 활성화). release에서 이 모드를 끌지는 따로 검토가 필요합니다.
