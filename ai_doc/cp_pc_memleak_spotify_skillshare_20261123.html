Spotify·Skillshare PC 메모리 재측정 — 10분 단위 덤프로 누수 여부 확인 (2026-11-23)

Confluence CP 메모리릭 전수 조사 (PC) 의 담당 CP 2종을 PC Chrome 143 에서 측정했다. 1차 측정은 두 앱 모두 '누수 의심'이었지만, 10분 단위 메모리 덤프로 다시 확인한 결과 둘 다 누수가 아니다. 1차 결과의 증가는 측정 도구(DevTools Network 도메인)가 만든 것이었다.

결론

27 Spotify 정상

2시간 연속 재생(22:12~00:19). footprint 96.5 → 104.9MB(+8.4MB), PSS 169 → 169MB, GC 후 heap 31.0 → 32.0MB. 할당자별 누적 없음.

1차: 159 → 304MB, 시간당 약 145MB → 측정 도구 영향

14 Skillshare 정상

2시간 무료 Trailer 34개 연속 재생(18:57~21:05). 0→10분 로딩 증가 후 평탄. 같은 순환 위치 60↔120분 footprint 389↔392MB, GC 후 heap 123.6↔123.4MB.

1·2차: Yellow / Red → 도구 영향 + 등락 고점 체크포인트

핵심 발견 — 측정 내내 붙어 있는 CDP 세션에서 Network.enable 을 켜 두면 렌더러가 DevTools 용으로 응답 본문을 Blink buffer partition 에 보관한다. 스트리밍 CP(오디오·영상 조각을 계속 받는 앱)는 이 때문에 메모리가 계속 늘어 '누수'처럼 보인다. 같은 방식으로 CDP 측정한 다른 CP 결과도 확인이 필요하다.

측정 도구 영향 확인 (Spotify, 18:51)

10분 덤프에서 Spotify 렌더러의 증가분은 memory-infra 할당자 중 partition_alloc/partitions/buffer 하나뿐이었다(0→10분 40.4 → 64.3MB, 나머지 할당자는 감소). Network 도메인을 켠 측정 세션만 닫고 바로 다시 쟀다.
