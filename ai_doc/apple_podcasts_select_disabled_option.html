Apple Podcasts 유해 콘텐츠 차단 메뉴에서 비활성화된 드롭박스 항목이 선택되는 현상

현상

Apple Podcasts 설정(유해 콘텐츠 차단 > 콘텐츠 제한) 드롭박스에서 선택할 수 없는(disabled) 첫 항목 "다음 중 하나를 선택하십시오."를 터치한 뒤 목록 바깥을 터치하면, 해당 항목이 선택된 상태로 바뀝니다. 기존에 선택되어 있던 값(예: 청소년 이용불가)은 사라집니다.

원인

웹 페이지 문제가 아니라 브라우저 엔진(Chromium Blink)의 결함입니다. 드롭박스 목록에서 터치 입력을 처리하는 경로가 비활성화 항목인지 검사하지 않습니다. 마우스 입력 경로에는 이 검사가 있어 PC에서는 발생하지 않고, 터치 전용인 ccNC에서 드러났습니다.

① 목록에서 비활성화 항목을 터치하면 기존 선택이 해제되고 아무 항목도 선택되지 않은 상태가 됩니다.
② 목록은 빈 값을 브라우저에 전달하고, 브라우저는 이를 첫 번째 항목(index 0)으로 해석합니다.
③ 목록 바깥을 터치해 닫으면, 브라우저가 비활성화 여부를 확인하지 않고 첫 번째 항목을 선택값으로 확정합니다.

관련 코드: third_party/blink/renderer/core/html/forms/select_type.cc ListBoxSelectType::DefaultEventHandler()의 GestureTap 처리부

확인 내용

  • 실차 재현: 웹페이지 스크립트가 아닌 브라우저가 직접 값을 변경(사용자 입력으로 발생한 change 이벤트, index 0)한 것을 로그로 확인했습니다.
  • Chromium 143 원본(OBIGO 수정 없음)에서도 터치 입력 조건으로 동일하게 재현됩니다.
  • 최신 Chromium(main, 2026-10-26 기준)에도 같은 코드가 남아 있어 upstream에서도 아직 수정되지 않았습니다.
  • 영향 범위: 브라우저 내장 드롭박스 목록을 쓰는 페이지에서, 비활성화 항목을 터치한 경우에만 발생합니다. Apple Podcasts에 한정되지 않습니다.

대책

터치 입력 경로에도 마우스 입력과 같은 비활성화 항목 검사를 추가했습니다. 비활성화 항목을 터치하면 아무 동작도 하지 않고 기존 선택값이 유지됩니다.

if (!select_->IsDisabledFormControl() &&
    !option->IsDisabledFormControl()) {   // 추가: 비활성화 항목 제외
  UpdateSelectedState(...);
  ListBoxOnChange();
}

비활성화 항목 터치 → 목록 닫기비활성화 항목 선택됨기존 선택값 유지
일반 항목 터치정상 선택정상 선택 (변경 없음)
마우스·키보드 입력정상정상 (변경 없음)

Chromium 143 원본 환경에서 수정 전 재현과 수정 후 해소를 확인했습니다. 적용 버전은 별도 안내드리겠습니다.
